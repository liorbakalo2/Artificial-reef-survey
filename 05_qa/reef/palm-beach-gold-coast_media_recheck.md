# Media re-check — Palm Beach Reef (palm-beach-gold-coast)

Date: 2026-09-25. Trigger: Lior's finding that two previously-accepted videos on other reef cards showed surfing at the beach but never the artificial reef itself; this card's full accepted media set was re-checked against the same rubric.

Rubric: `structure_visible` (reef/boulders visible — construction, exposed, aerial of footprint) / `reef_effect_visible` (structure submerged but its effect unmistakable at the reef's location, source ties it there) / `site_context_only` (beach/town/generic surfing, no visible link to reef) / `unrelated_or_wrong_site` / `could_not_load`.

**Process note (data-integrity caveat):** the shared scratchpad used by this task is reused by parallel subagents in the same session. A first download pass using generic filenames (`img1.jpg`…`img4.jpg`) was silently overwritten mid-task by another subagent's files, producing completely wrong pictures (an unrelated Burkitts-Reef 1980 petition sketch, an excavator scene, two generic surf shots) that did **not** match the card's own captions. This was caught by cross-checking downloaded file sizes/dimensions against the `Content-Length`/`<img width/height>` reported live by the source pages (e.g. the Cru Collective page states `Palm-Beach-Artificial-Reef-Completion.jpg` is 791×664 px and 104,402 bytes; the first "img2.jpg" downloaded was 862×575 and 137,285 bytes — a mismatch). All four images were re-downloaded a second time to reef-specific filenames (`pbgc_img1..4.jpg`) and the byte sizes/dimensions now match the live source pages exactly, confirmed correct, and viewed. **All classifications below are from this verified second pass.** No other reef's card should be assumed contaminated by this — it appears specific to this run's temp-file collision — but future re-checks should use per-reef filenames in the scratchpad, not generic `imgN.jpg`.
