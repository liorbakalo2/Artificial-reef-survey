# Media verification — Narrowneck Reef (Gold Coast), adversarial pass

Method: for each web image, fetched the source page (WebFetch), downloaded the image with `curl -L -A "Mozilla/5.0"`, viewed it with Read, and compared the visible content against the claimed caption. Ran a no-Referer `curl -sI` hotlink test on every accepted image. For videos, ran `yt-dlp --dump-single-json --skip-download` plus a YouTube oEmbed check for embeddability. No video-frame files existed on disk for this slug (folder empty), so no frame table is needed. Checked Lior's own extracted pptx images for ones that depict this specific reef.

**Important finding:** on the first (batched/parallel) download+view pass, 3 of the 5 images (img1 Wikimedia beach photo, img2 ICM headland photo, img4 ICM marine-life photo) rendered as clearly wrong/unrelated content when viewed (a rock-barge/dredging photo, a UK-looking pebble beach with an unrelated "Construction Operations Keep Out" sign, and excavators building a rock groyne, respectively) — none of which matched their captions, and img1's EXIF even showed a 2011 Canon DSLR timestamp inconsistent with the claimed 2026 photo date. Re-downloading each of these three individually (not batched) produced different file hashes and correct, caption-matching content in every case. This was a tool/CDN race-condition artifact of parallel fetching, not a problem with the source URLs. Treated as a process note, not a rejection reason — final verdicts below are based on the individually re-verified downloads.
